# MusicPlayer

A modern, high-performance local audio player for Android built with React Native and Expo. The interface draws inspiration from the dot-matrix minimalism of Nothing OS, the fluid ergonomics and tactile sheet transitions of Apple Music, and polished interaction patterns found in leading modern design systems.

---

## Overview

MusicPlayer was developed as a clean, local-first alternative to bloated streaming clients. Most modern mobile players prioritize algorithmic feeds, social integrations, and subscription banners over the actual music stored on the user's device. 

This project strips away all external distractions, providing a focused, responsive listening environment. It marries strict visual restraint with robust native audio playback, offering comprehensive queue control, sound personalization, and an intelligent device scanner that keeps local libraries clean from voice notes and notification sounds.

---

## Design Philosophy

The application's aesthetic sits at the intersection of several distinct industrial and interface design traditions:

* **Nothing OS Influence**: Geometric layouts, monochromatic high-contrast palette, and selective use of monospaced and dot-matrix typography (via the Doto and Geist typefaces) to evoke a functional, hardware-inspired instrument feel.
* **Apple and iOS Interaction Design**: Layered bottom sheet presentations, pill-shaped floating navigation docks, real-time spring physics via Reanimated, and ambient color bleeding from album artwork.
* **Modern Material Nuance**: Subtle elevation, carefully tuned tap response, and generous touch targets that keep single-handed navigation effortless.
* **Enforced Light Aesthetic**: Built around a bright `#F9F9F9` canvas with dark contrasting controls and text, ensuring consistent legibility and interface branding regardless of the operating system's system-wide dark mode toggle.

## Core Features

### 1. Audio Engine and Background Playback
* **Native Foreground Service**: Uses `react-native-track-player` to anchor playback in an Android foreground service. Playback remains uninterrupted when switching apps, locking the device, or when the system enters deep battery-saving states.
* **Lock Screen and Notification Center**: Full system media notification support with artwork thumbnail, scrubbing timeline, skip back/forward, and play/pause controls.
* **DSP and Audio Customization**:
  * Variable playback rate (from 0.5x up to 2.0x).
  * Pitch adjustments for altered playback tuning.
  * Simulated audio effect presets: Bass Boost, Treble Boost, and Spatial Ambience.
  * Configurable crossfade between queue items to eliminate awkward gaps.
* **Dynamic Artwork Gradient**: An optional visual mode that samples dominant color profiles from album artwork and renders an ambient top-down linear gradient directly inside the full-screen player modal.

### 2. Smart Media Indexer and Junk Filter
Most Android media stores lump audio files together, mixing personal music with voice memos, call recordings, and app sound effects. The built-in media scanner automatically filters out non-musical audio:
* **Format-Specific Filtering**: Filters out `.opus` and `.amr` files commonly generated by messenger voice notes.
* **Pattern Matching**: Regex-based file name checks targeting WhatsApp patterns (`PTT-\d+`, `AUD-\d+-WA\d+`), voice recorder prefixes (`REC_*`, `VOICE_*`), and call recording outputs.
* **Directory Path Exclusion**: Ignores specific folders such as `WhatsApp Audio`, `WhatsApp Voice Notes`, `Notifications`, `Ringtones`, and `Alarms`.
* **Duration Thresholding**: Automatically disregards files shorter than 30 seconds to prevent alert sounds, UI clicks, and brief voice snippets from appearing in track lists (tracks with missing metadata duration tags are safely retained).
* **Demo Catalog**: Ships with a pre-indexed 30-track offline demo library for development testing when no local media files are loaded onto the device or emulator.

### 3. Queue and Playback Management
* **Flexible Loop and Randomization**: Off, Repeat All, Repeat Single Track, and true randomized Shuffle mode with track-history preservation.
* **Dynamic Queue Operations**: Tap any track to spawn an active playback session, insert tracks to play next, or queue songs for subsequent playback.
* **Mini-Player Dock**: A persistent floating mini-player bar positioned directly above the navigation bar. Displays current track title, artist, progress indicator, and quick play/pause toggles, and expands into the full player on tap.

### 4. Playlist and Library Architecture
* **Full Playlist Customization**: Create, rename, reorganize, and delete custom playlists.
* **Cover Art Studio**: Assign curated graphic preset covers or pick custom local device images. Includes an alignment selector allowing users to set cover art focus to left, center, or right.
* **Local Metadata Editing**: Modify track titles, artist names, and album tags locally within the app's database without altering the underlying files on disk.
* **Favorites System**: Direct one-tap favoriting accessible across track rows, context options sheets, and the main player view.

### 5. Synchronized & Plain Lyrics
* **Real-time Synchronized Lyrics**: Time-synced `.lrc` playback with smooth automatic scrolling that highlights the active line and keeps upcoming lyrics in view.
* **Interactive Line Seeking**: Tap any lyric line to instantly jump playback to that timestamp.
* **Lyrics Provider**: Powered by the open and community-driven **[LRCLIB](https://lrclib.net)** service.

## State and Data Flow

1. **Initialization**: On launch, `App.js` locks the application color scheme to light mode, pre-loads the Google Fonts (Geist and Doto), and initializes the `PlayerContext`.
2. **Media Loading**: `musicService.js` queries `expo-media-library`. Raw assets pass through `isJunkOrVoiceRecording` to remove voice clips and short notification audio. Valid tracks are mapped and hydrated into the primary track store.
3. **Audio Routing**: When playback begins, `trackPlayerService.js` coordinates with the native Android audio subsystem. If native TrackPlayer initialization encounters environment limitations (e.g. running in standard simulators), playback seamlessly degrades to the secondary audio engine.
4. **Persistence**: Changes to playlists, metadata edits, favorites, and user audio preferences (speed, pitch, crossfade, dynamic gradient toggle) are immediately serialized to disk via `storageService.js` using `@react-native-async-storage/async-storage`.

## Tech Stack Details

* **Runtime Environment**: React Native 0.86.3 / Expo SDK 57 (Bare Native / Dev Client)
* **Language Runtime**: React 19
* **Audio Layer**:
  * Primary: `react-native-track-player` 4.1.2 (applied with custom patch for modern React Native architecture compatibility)
  * Secondary / Fallback: `expo-audio`
* **Navigation**: `@react-navigation/bottom-tabs` v7, `@react-navigation/native` v7
* **Motion & Gestures**: `react-native-reanimated` 4.5.1
* **Storage**: `@react-native-async-storage/async-storage` 2.2.0
* **Typography**: `@expo-google-fonts/geist`, `@expo-google-fonts/doto`
* **Icons**: `lucide-react-native`
* **Lyrics Provider**: [LRCLIB](https://lrclib.net) (Open REST API providing time-synchronized `.lrc` and plain lyrics)
* **Styling**: Vanilla React Native `StyleSheet` with unified design token primitives

## Installation and Local Setup

### Prerequisites

* Node.js LTS (v20.x or higher)
* Android SDK (API Level 34 or higher) with command line tools and emulator / physical device configured
* Expo CLI (`npx expo`)

### Step-by-Step Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/your-username/MusicPlayer.git
   cd MusicPlayer
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Ensure native patches are applied:
   ```bash
   npx patch-package
   ```

4. Prebuild native directories (if building directly with native toolchains):
   ```bash
   npx expo prebuild --platform android
   ```

5. Build and launch the development client on Android:
   ```bash
   npx expo run:android
   ```

6. Start the Metro bundler:
   ```bash
   npx expo start --dev-client
   ```

*Note: Because this project relies on custom native modules (`react-native-track-player`), it cannot run inside the standard pre-compiled Expo Go sandbox. It must be executed via `expo run:android` or built using an EAS Development Build (`eas build --profile development`).*

## Android Permissions Breakdown

The application requests specific permissions in `app.json` strictly necessary for its local-first capabilities:

| Permission | Purpose |
| :--- | :--- |
| `READ_MEDIA_AUDIO` | Required on Android 13+ (API 33+) to index local audio files. |
| `READ_EXTERNAL_STORAGE` | Fallback permission for Android 12 and older to discover device media. |
| `FOREGROUND_SERVICE` | Keeps audio playback active when the app is backgrounded or minimized. |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | Identifies the service type for the Android 14+ system media engine. |
| `MODIFY_AUDIO_SETTINGS` | Facilitates audio routing, equalizing, and hardware volume integration. |
| `RECORD_AUDIO` | Enables hardware-level audio visualizer spectrum data collection. |
